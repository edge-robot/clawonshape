  capture one, because running `openclaw` is not permitted here. `tests/fixtures/native-mcp-status-2026.9.9.json`
  remains the only fixture. Mitigation: `buildMcpStatusEntries` (`dist/mcp-cli-mI2r-A7N.mjs` vs. 9.9

  The documented shape in `docs/cli/mcp/json-output.md` only changed the wording "probe" to "check". I ask the
  architect to capture the fixture during E2E and issue a follow-up prompt to add it.
- **Doctor config migration.** The plugin's config keys are all declared, and the plugin is not bundled. The
  2026.10.10 doctor migration list (`docs/gateway/doctor/config-migrations.md`) names no `claw-onshape` keys.
  This was checked offline only; step 1 of the E2E confirms it.
- **`engines.node` is `>=24.0.0`** while OpenClaw 2026.10.10 requires `>=24.16.0`. I did not change it because
  the upgrade does not force it and it does not affect behaviour; the host's OpenClaw install enforces the floor.
  The architect may want to align it.
- **Stale version comments.** Some comments still say "OpenClaw 2026.9.9":
  - `src/native-secret-file.d.ts:1`
  - `src/dashboard.ts:41`
  - `src/work-context-service.ts:52`
  - `src/mcp.ts:74`

  The facts they state still hold for 2026.10.10, as verified above. I left them unchanged under the
  no-behaviour-change rule.
- **`scripts/host-diagnostics.mjs:72-73`** hardcodes `researchedHost: '2026.9.9'`. On a 2026.10.10 host it will
  report `matchesResearchedHost: false`. That output is correct, but operators may read it as an error. I left
  it unchanged because it is diagnostics only and the upgrade does not force a change. Decision for the
  architect.
- **SDK behaviour I could not test offline:**
  - gateway registration modes and service start
  - `registerRuntimeLifecycle` dispose ordering
  - `runtime.channel.outbound.loadAdapter`
  - session-action routing in the new Control UI architecture

  The types and the identical JSON limits suggest these are compatible. Only the live E2E proves it.
