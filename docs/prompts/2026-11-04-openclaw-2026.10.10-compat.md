# Plugin compatibility with OpenClaw 2026.10.10 (#25)

## Goal

Make the `claw-onshape` plugin build, type-check, test and pack against OpenClaw `2026.10.10`
(the current stable release, 2026-11-03) without changing its behaviour. The architect then rolls
it out to the cluster, which today runs OpenClaw `2026.9.9` with plugin `0.3.0-rc.3`.

## Context

- `package.json` pins `openclaw` exactly to `2026.9.9` in `peerDependencies` and
  `devDependencies`. npm publishes `openclaw@2026.10.10` (engines: node `>=24.16.0 <25 || >=26.1.0`).
- Release notes: <https://github.com/openclaw/openclaw/releases> and
  <https://docs.openclaw.ai/>. The 9.x extended-stable notes mention that `openclaw doctor` removes
  unknown config keys during updates; check whether the plugin's `openclaw.plugin.json`
  `configSchema` still covers every key the plugin reads.
- Plugin entry points: `src/index.ts`, `openclaw.plugin.json`; plugin SDK imports under `src/**`.

## Binding constraints and prohibitions

- **No behaviour change.** Only changes that the new OpenClaw version forces (types, imports,
  renamed SDK APIs, manifest schema). Each such change is listed in the report with the
  OpenClaw source or doc link that forced it.
- No change under `docs/interface/**`, `docs/ADR.md`, `spec.md`, `deploy/`, `Containerfile`,
  `.devcontainer/`, `scripts/dev.sh`, `.claude/`.
- `peerDependencies.openclaw`: use the range `>=2026.9.9 <2026.11.0` only if the code still works
  with both versions (keep `2026.9.9` as the rollback runtime); otherwise pin `2026.10.10` and say so.
  `devDependencies.openclaw`: `2026.10.10`.
- Version: bump to `0.3.0-rc.4`.
- No live Onshape calls. No deployment; never push.
- Work only on `feat/21-work-context-selection`. No branches, worktrees or stashes.

## Steps

1. Check branch and HEAD, `git status`. Record the baseline on `2026.9.9`: `npm run typecheck`,
   `npm test`, `npx biome ci .`.
2. Raise the dependency, `npm install` (lockfile update is expected), rerun all checks.
3. Fix breaks with the smallest change. Search the OpenClaw package for removed or renamed plugin
   SDK exports you import.
4. Verify `openclaw.plugin.json` against the 2026.10.10 manifest schema (the package ships it, or
   see the docs).
5. Bump the version to `0.3.0-rc.4`, run `npm pack --dry-run` and list the file count.
6. Commit in logical commits.
