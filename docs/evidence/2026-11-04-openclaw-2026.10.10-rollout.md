# OpenClaw 2026.10.10 rollout with plugin 0.3.0-rc.4 (2026-11-04)

Issue: edge-robot/clawonshape#25. Matrix row: plugin 0.3.0-rc.4 on OpenClaw 2026.10.10
([interface/onshape-mcp.md §9](../interface/onshape-mcp.md#9-versioning-and-compatibility)).
Operator: the user ran the `--execute` commands; the architect ran previews and checks.

## Preparation

The Lead config had drifted outside Clawake on 2026-10-30. The drift was a local wiki agent
`assistant` with the `memory-wiki` plugin, and the Discord binding moved to that agent. Two changes
on 2026-11-04 fixed it, both with `openclaw agents unbind/bind` in the container; the gateway
hot-reloaded each one:

- **Discord routing back to the Lead.** Removed `assistant <- discord accountId=*`; restored
  `clawcad-robotics-lead <- discord accountId=*`.
- **Unmanaged binding removed.** Removed `clawcad-robotics-lead <- a2a accountId=*`. It made
  `clawake upgrade`/`setup` refuse the Lead ("unmanaged A2A routing bindings"). The Lead is the
  default agent, so A2A routing is unchanged.

The wiki agent stays configured but unbound. Its local data is git-ignored.

## E2E result (11:25–11:28 UTC)

- **Render: pass.** The Lead ran `onshape_delegate_render` → signed A2A → Engineer
  `onshape_render`. The Engineer returned `status: ok` on `wegwerf-document / Part Studio 1`, and
  the PNG was delivered in Discord.
- **Inspect: pass at the Engineer, timeout at the Lead.**
  - The Engineer ran `onshape_api_call getPartStudioFeatures` (read-only), then `onshape_render`.
  - `onshape_complete_task` returned `status: ok` at 11:27:41: 80 × 50 × 4 mm, four holes,
    pinned to microversion `0108fa2b…`.
  - The Lead's `onshape_delegate_task` failed at 11:27:44 with "OpenClaw dynamic tool call timed
    out after 90000ms", 3 s after the Engineer finished. The Lead told the user it had timed out.
  - The Engineer turn lasted about 88 s. The 90 s limit is OpenClaw's dynamic tool call timeout,
    not a plugin constant. Whether it changed between 2026.9.9 and 2026.10.10 is unverified.
- **Cause, as far as observed:** OpenClaw 2026.10.10 code mode exposes the plugin tools with the
  namespace prefix `openclaw__` (for example `openclaw__onshape_render`). `AGENTS.md` and the skills name
  them unprefixed. Each first call failed with `tools.<name> is not a function`, and the agent
  searched `ALL_TOOLS` before retrying. That cost 4–5 extra turns in the inspect run. No extra
  Onshape calls resulted.
- **Onshape calls:** counter readings were not recorded.
- **Pre-existing, not caused by the upgrade:** the Onshape connection had been
  `reconnect_required` since at least 2026-11-03 (edge-robot/clawonshape#24). The user reconnected
  before the E2E.
